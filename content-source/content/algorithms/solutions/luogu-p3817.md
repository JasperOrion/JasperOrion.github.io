# P3817 小 A 的糖果

## 题目

有 `n` 个糖果盒，第 `i` 个盒子中有 `a[i]` 颗糖果。每次可以从任意盒子中吃掉一颗糖，要求最终任意两个相邻盒子的糖果数之和都不超过 `x`，求至少需要吃掉多少颗糖。

即最终需要满足：

```text
a[i - 1] + a[i] <= x
```

## 思路

### 优化目标与当前决策

目标是以最小代价满足所有相邻约束。从左向右扫描，每次处理当前相邻的两个盒子 `a[i - 1]` 和 `a[i]`。

如果二者之和超过 `x`，超出量为：

```text
excess = a[i - 1] + a[i] - x
```

为了让当前相邻关系合法，任何方案都至少需要吃掉 `excess` 颗糖。因此当前最小代价已经确定，问题只剩下：应该从哪个盒子吃？

### 贪心选择

在保证 `a[i - 1] <= x` 的前提下，把超出的糖全部从右盒 `a[i]` 吃掉：

```cpp
answer += excess;
a[i] -= excess;
```

原因是：

- `a[i - 1]` 属于已经处理过的前缀；
- `a[i]` 还会参与下一组约束 `a[i] + a[i + 1]`；
- 减少 `a[i]` 不会破坏之前的约束，还会让下一组约束更容易满足。

这体现了 [贪心算法](/articles/algorithms/concepts/贪心算法/) 的核心：只付出当前无法避免的最小代价，并把修改放在对未来最有利的位置。

### 必须先处理第一个盒子

第一次循环前不一定满足 `a[0] <= x`。例如：

```text
a = [10, 1]
x = 5
```

当前超出量为 6，但第二盒只有 1 颗糖，不能直接从第二盒吃掉 6 颗。

由于糖果数非负，为了让第一对盒子满足限制，第一盒最终一定不能超过 `x`。因此先执行：

```cpp
if (a[0] > x) {
    answer += a[0] - x;
    a[0] = x;
}
```

之后每轮处理都会保证当前右盒不超过 `x`，从而维持不变量：

```text
进入第 i 轮时，a[i - 1] <= x
```

于是：

```text
excess = a[i - 1] + a[i] - x <= a[i]
```

超出量一定可以全部从右盒吃掉，不会出现负数。

## 正确性证明

### 引理一：当前至少需要吃掉 `excess` 颗

当 `a[i - 1] + a[i] > x` 时，要把二者之和降到不超过 `x`，任何合法方案都至少需要减少：

```text
a[i - 1] + a[i] - x
```

颗糖。算法恰好吃掉这么多，没有额外代价。

### 引理二：从右盒吃不会让后续答案变差

当前左盒 `a[i - 1]` 不再参与后续尚未处理的约束，右盒 `a[i]` 还会参与下一组约束。把必要的减少量放在右盒，不影响已经满足的前缀，并使下一组相邻和不增。

### 归纳结论

处理完第 `i` 轮后：

1. 从第一对到当前对的所有相邻约束均已满足；
2. 为满足这些前缀约束，算法付出的代价最小；
3. 当前右盒尽可能小，对后续处理最有利。

因此从左到右处理完整个数组后，得到的总吃糖数量是全局最小值。

## 解法

### 方法一：预处理第一盒后从左到右贪心

- 时间复杂度：`O(n)`。
- 空间复杂度：`O(n)`；若边读边处理，可优化为 `O(1)` 额外空间。

```cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n;
    long long x;
    cin >> n >> x;

    vector<long long> a(n);
    for (long long& candy : a) {
        cin >> candy;
    }

    long long answer = 0;

    // 建立不变量：第一次循环前 a[0] <= x
    if (a[0] > x) {
        answer += a[0] - x;
        a[0] = x;
    }

    for (int i = 1; i < n; ++i) {
        long long excess = a[i - 1] + a[i] - x;

        if (excess > 0) {
            answer += excess;
            a[i] -= excess;
        }
    }

    cout << answer << '\n';
    return 0;
}
```

### 方法二：右盒优先、不足再减少左盒

也可以不预处理第一盒。每次冲突时先尽量从右盒吃；如果右盒不足，再从左盒吃。减少左盒只会让之前的约束更宽松，因此仍然安全。
kan
这种写法更通用，但状态变化较多，正确性说明不如方法一简洁。

```cpp
for (int i = 1; i < n; ++i) {
    long long excess = a[i - 1] + a[i] - x;
    if (excess <= 0) continue;

    answer += excess;

    long long eatRight = min(a[i], excess);
    a[i] -= eatRight;
    excess -= eatRight;

    if (excess > 0) {
        a[i - 1] -= excess;
    }
}
```

## 样例分析

输入：

```text
6 1
1 6 1 2 0 4
```

从左向右处理：

| 当前相邻盒子 | 当前和 | 超出量 | 修改后的右盒 | 累计答案 |
|--------------|-------:|-------:|---------------:|---------:|
| `1, 6` | 7 | 6 | 0 | 6 |
| `0, 1` | 1 | 0 | 1 | 6 |
| `1, 2` | 3 | 2 | 0 | 8 |
| `0, 0` | 0 | 0 | 0 | 8 |
| `0, 4` | 4 | 3 | 1 | 11 |

最终数组为：

```text
[1, 0, 1, 0, 0, 1]
```

答案为 11。

## 易错点

- 没有预处理 `a[0] > x`，导致 `excess > a[i]` 时把右盒减成负数。
- 只累加答案，没有同步修改数组，导致后续相邻和计算错误。
- 当前相邻和恰好等于 `x` 时不需要操作。
- 使用 `int` 保存答案，极端数据下可能溢出，应使用 `long long`。
- 误以为贪心题一定需要排序；本题的关键是从左到右的处理顺序和前缀不变量。

## 总结

- 当前超出量是任何合法方案都无法避免的最低代价。
- 优先减少右盒，可以同时帮助下一组约束。
- 预处理第一盒后，`a[i - 1] <= x` 成为核心不变量。
- 每轮都达到当前前缀的最小代价，因此最终得到全局最优解。
