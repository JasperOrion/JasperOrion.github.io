# 贪心算法

## 定义

贪心算法（Greedy Algorithm）在每个决策阶段选择当前看来最优的方案，并且通常不撤销之前的选择。它的目标是通过一系列局部最优选择构造全局最优解。

> [!important]
> “选择当前最优”只是策略；能够证明该选择不会失去全局最优解，才构成正确的贪心算法。

## 为什么需要贪心

当问题包含大量选择时，枚举所有方案可能产生指数级搜索空间。若问题具有贪心选择性质，就能在每一步排除其他选择，通常通过一次排序和一次线性扫描求解。

常见时间复杂度为 `O(n log n)`：排序需要 `O(n log n)`，扫描需要 `O(n)`。

## 使用条件

### 贪心选择性质

问题至少存在一个全局最优解，其中包含当前的贪心选择。证明时通常说明：即使某个最优解没有使用贪心选择，也可以把它替换为贪心选择，而且答案不会变差。

### 最优子结构

做出贪心选择后，剩余问题的最优解能够与当前选择组合成原问题的最优解。

最优子结构也是 动态规划 的基础，但有最优子结构并不意味着一定能使用贪心。

## 通用解题框架

1. **明确优化目标**：确认问题要求最大化或最小化数量、收益、时间、代价还是操作次数。
2. **确定当前决策**：明确每一步选择的是区间、物品、边、任务还是某个操作。
3. **提出局部标准**：例如最早结束、单位收益最高、增量代价最小或对后续限制最小。
4. **构造反例**：用小数据、极端值、相等元素和冲突选择攻击策略。
5. **证明选择安全**：说明当前选择不会让答案变差。
6. **实现并验证**：排序或使用优先队列后扫描，检查边界条件。

排序和优先队列只是帮助找到当前最优选择的工具，不是贪心的本质。

```cpp
sort(items.begin(), items.end(), compare);

for (const auto& item : items) {
    if (canChoose(item)) {
        choose(item);
        updateState(item);
    }
}
```

## 正确性证明

### 交换论证

1. 假设存在一个最优解，但它没有首先使用贪心选择。
2. 将最优解中的某个选择换成贪心选择。
3. 证明交换后的解仍然合法，而且答案不会变差。
4. 因而至少存在一个包含贪心选择的最优解。

交换论证常用于区间调度、任务排序和排序不等式。

### 领先法

证明贪心方案执行到任意阶段时，在关键指标上始终不劣于其他方案。例如，完成前 `k` 个任务的时间始终不晚于其他安排。

## 经典实例：活动安排

给定若干具有开始时间和结束时间的活动，同一时间只能参加一个活动，要求选择尽可能多的活动。

贪心策略是按照结束时间从早到晚排序，每次选择与上一个活动不冲突的活动。

```cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

struct Activity {
    int start;
    int end;
};

int main() {
    int n;
    cin >> n;

    vector<Activity> activities(n);
    for (auto& activity : activities) {
        cin >> activity.start >> activity.end;
    }

    sort(activities.begin(), activities.end(),
         [](const Activity& a, const Activity& b) {
             if (a.end != b.end) return a.end < b.end;
             return a.start < b.start;
         });

    int answer = 0;
    int lastEnd = -1;

    for (const auto& activity : activities) {
        if (activity.start >= lastEnd) {
            ++answer;
            lastEnd = activity.end;
        }
    }

    cout << answer << '\n';
}
```

- 时间复杂度：`O(n log n)`。
- 扫描部分的空间复杂度：`O(1)`，不计排序内部空间。

设贪心算法选择结束最早的活动 `G`，某个最优方案选择的第一个活动是 `A`。由于 `G` 的结束时间不晚于 `A`，将 `A` 换成 `G` 不会影响后续活动，活动总数也不会减少。因此至少存在一个以 `G` 开始的最优方案。

## 失败反例：特殊硬币找零

硬币面值为 `1、3、4`，目标金额为 `6`。最大面值优先得到 `4 + 1 + 1`，需要 3 枚硬币；实际最优方案 `3 + 3` 只需要 2 枚。

这说明局部最优不一定产生全局最优，贪心策略必须证明。

## 贪心与动态规划

| 特征 | 贪心 | 动态规划 |
|------|------|----------|
| 每一步保留的选择 | 通常只保留一个 | 综合多个可能状态 |
| 是否回头比较 | 通常不会 | 通过状态转移比较历史方案 |
| 核心条件 | 贪心选择安全 | 无后效性、最优子结构、重复子问题 |
| 设计难点 | 找到策略并证明 | 定义状态、转移和初始化 |
| 常见复杂度 | `O(n)` 或 `O(n log n)` | 通常高于对应贪心解法 |

## 常见题型

- 区间调度：优先选择结束时间早的区间。
- 区间覆盖：在可选范围内选择延伸最远的区间。
- 分数背包：优先选择单位价值最高的物品。
- Huffman 合并：每次合并权值最小的两个元素。
- 最小生成树：Kruskal、Prim。
- 单源非负权最短路：Dijkstra。
- 排序不等式与任务调度：通过交换论证确定顺序。

详见 贪心主题索引。

## 易错点

- 看到“最大”“最小”便直接使用贪心。
- 把排序当作贪心的本质。
- 只验证样例，不主动寻找反例。
- 写出了策略，却无法证明选择安全。
- 在适合动态规划的问题中错误丢弃其他状态。

## 解题自检

1. 优化目标是什么？
2. 每一步具体决定什么？
3. 局部最优标准是什么？
4. 为什么该选择不会破坏后续最优解？
5. 能否用交换论证或领先法证明？
6. 能否构造反例推翻这个策略？
