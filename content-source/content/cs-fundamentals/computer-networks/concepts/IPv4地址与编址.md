# IPv4 地址与编址

## 定义

**IP 地址**是分配给连接到因特网上的每台主机（或路由器接口）的**全球唯一 32 位标识符**。IP 地址标识的是**主机接口**而非主机本身——路由器每个接口一个 IP，分属不同网络。

> 点分十进制表示：`192.168.1.10` = `11000000 10101000 00000001 00001010`

## 一、分类编址的 IPv4 地址

早期的 IP 地址按"网络规模"分为五类，看首字节就能区分——因为每个类的前几位是固定的。

### 五类地址的位结构

32 位 IP 地址按"前导位"区分类型——看前几位就能知道是哪个类、网络/主机号各占多少位：

```
           ├─── 固定前缀 ───┤├───────────── 可分配部分 ──────────────┤

A :       0│───── net(7) ───│───────────── host(24) ──────────────│  1677万/网
           │                 └─────── 首字节 1~126 ────────────────┘  126 网络

B :      10│───── net(14) ───│─────────── host(16) ──────────────│  6.5万/网
           │                  └─────── 首字节 128~191 ─────────────┘  16384 网络

C :     110│──────── net(21) ──────│──── host(8) ───│                254/网
           │                        └── 首字节 192~223 ─┘              209万 网络

D :    1110│─────────── multicast(28) ─────────────│                  多播
           │                                        └── 224~239 ──┘

E :    1111│──────────── reserved(28) ────────────│                    保留
           │                                        └── 240~255 ──┘
```

> 前导位 `0` = A 类，`10` = B 类，`110` = C 类，`1110` = D 类，`1111` = E 类。`│` 左侧为固定前缀，右侧为可分配部分。

| 类别 | 首字节范围 | 网络号位数 | 主机号位数 | 最多网络数 | 每网最多主机数 |
|------|-----------|-----------|-----------|-----------|---------------|
| **A** | 1 ~ 126 | 7 | 24 | 126 | $2^{24}-2 = 16,777,214$ |
| **B** | 128 ~ 191 | 14 | 16 | 16,384 | $2^{16}-2 = 65,534$ |
| **C** | 192 ~ 223 | 21 | 8 | 2,097,152 | $2^8-2 = 254$ |
| **D** | 224 ~ 239 | — | — | — | 多播地址 |
| **E** | 240 ~ 255 | — | — | — | 保留 |

> **注意**：网络数 和 每网主机数 都减了 2，原因不同——前者因为 `0.x.x.x` 和 `127.x.x.x` 被特殊用途占用，后者因为全 0（网络地址）和全 1（广播地址）。

### A 类地址（巨型网络）

**位结构**：`0 + 7 位网络号 + 24 位主机号`

```
A 类 (0+7+24):   0nnnnnnn│hhhhhhhh│hhhhhhhh│hhhhhhhh      1677万/网
                 ^^^^^^^ ^^^^^^^^^^^^^^^^^^^^^^^^^^^
                 net(7)            host(24)
                 固定bit0=0
```

**为什么网络号只有 7 位而不是 8 位？**
因为首字节最高位固定为 `0`，所以剩下的编码空间只有 $2^7 = 128$ 个值。但这 128 个中：

- `0.0.0.0/8` → 特殊保留（表示"本网络本主机"）
- `127.0.0.0/8` → 回环地址（本地协议栈测试，`127.0.0.1` 最常用）
- 实际可分配：$2^7 - 2 = 126$ 个 A 类网络

**范围**：`1.0.0.0 ~ 126.255.255.255`

**每网主机数**：$2^{24} - 2 = 16,777,214$ 台（约 1677 万）

**为什么减 2？** 主机号全 0 是**网络地址**（标识网络本身），主机号全 1 是**广播地址**（发往该网络所有主机）。

> 实例：`10.0.0.0/8` 是一个 A 类私有网络。其中 `10.0.0.0` 是网络地址，`10.255.255.255` 是广播地址，`10.0.0.1 ~ 10.255.255.254` 约 1677 万个地址可用。

---

### B 类地址（中型网络）

**位结构**：`10 + 14 位网络号 + 16 位主机号`

```
B 类 (2+14+16): 10nnnnnn│nnnnnnnn│hhhhhhhh│hhhhhhhh      6.5万/网
                 ^^^^^^^^^^^^^^^ ^^^^^^^^^^^^^^^^^^
                     net(14)           host(16)
                 固定bit0~1=10
```

**首字节范围推导**：前两位固定 `10`，剩余 6 位从 `000000` 到 `111111`：
- 最小值：`10000000` = 128
- 最大值：`10111111` = 191
- 所以 B 类 = `128.0.0.0 ~ 191.255.255.255`

**网络数**：$2^{14} = 16,384$ 个（网络号没有"减 2"的问题，因为 `128.0` 和 `191.255` 都可以正常分配）

**每网主机数**：$2^{16} - 2 = 65,534$ 台（减 2 原因同 A 类：全 0 网络地址 + 全 1 广播地址）

> 实例：`172.16.0.0/12` 是一个 B 类风格的私有地址段（实际横跨了 16 个连续的 B 类网络）。

---

### C 类地址（小型网络）

**位结构**：`110 + 21 位网络号 + 8 位主机号`

```
C 类 (3+21+8): 110nnnnn│nnnnnnnn│nnnnnnnn│hhhhhhhh       254/网
                 ^^^^^^^^^^^^^^^^^^^^^^^ ^^^^^^^^
                        net(21)          host(8)
                 固定bit0~2=110
```

**首字节范围推导**：前三位固定 `110`，剩余 5 位从 `00000` 到 `11111`：
- 最小值：`11000000` = 192
- 最大值：`11011111` = 223
- 所以 C 类 = `192.0.0.0 ~ 223.255.255.255`

**网络数**：$2^{21} = 2,097,152$ 个（约 209 万个！看似很多，但每个网络只有…）

**每网主机数**：$2^8 - 2 = 254$ 台（只有 254 台可用）

> 实例：`192.168.1.0/24` 是最常见的家用路由器默认子网。可用地址 `192.168.1.1 ~ 192.168.1.254`，`192.168.1.255` 是广播地址。

---

### D 类和 E 类地址

**D 类（多播地址）**：`1110 + 28 位多播组 ID`

```
D 类 (4+28): 1110mmmm│mmmmmmmm│mmmmmmmm│mmmmmmmm      多播
              ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
                    multicast(28)
             固定bit0~3=1110          首字节 224~239
```

- **首字节**：`11100000`=224 ~ `11101111`=239
- 没有网络号/主机号的划分，整个地址标识一个**多播组**
- 一台主机可加入多个多播组。典型用途：视频会议、IPTV、OSPF（`224.0.0.5` 和 `224.0.0.6`）

**E 类（保留）**：`1111 + 28 位保留`

```
E 类 (4+28): 1111rrrr│rrrrrrrr│rrrrrrrr│rrrrrrrr       保留
              ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
                     reserved(28)
             固定bit0~3=1111          首字节 240~255
```

---

### 为什么都要"-2"？

这是分类编址中最重要的计数规则，但两种"减 2"的原因不同：

| 减 2 的位置 | 原因 | 影响什么 |
|------------|------|---------|
| **网络号减 2**（仅 A 类） | `0.x.x.x` 保留 + `127.x.x.x` 回环 | 只有 A 类网络数 = 126 而非 128 |
| **主机号减 2**（A/B/C 通用） | 全 0 = 网络地址 + 全 1 = 广播地址 | 每网可用主机数 = $2^k - 2$ |

---

### A/B/C 三类对比一览

```
       每网主机数              网络数              评 价
A 类   ████████████████████   ██                规模极大，远超需求 → 浪费
       1677 万                126

B 类   ██████████             ██████            规模适中，数量太少 → 耗尽
       6.5 万                 16384

C 类   █                      ████████████████  数量充足，规模太小 → 不够用
       254                    209 万
```

> 规律：**网络越大数量越少，网络越小数量越多。** 但没有任何类刚好适合"中等规模"的需求——这正是分类编址的致命缺陷。

### 特殊用途 IP 地址

| 地址 | 含义 | 用途 |
|------|------|------|
| `0.0.0.0` | 本网络本主机 | 仅作源地址（DHCP 初始请求） |
| 主机号全 0 | **网络地址** | 标识网络本身（如 `192.168.1.0`） |
| 主机号全 1 | **直接广播地址** | 发往该网络所有主机（如 `192.168.1.255`） |
| `255.255.255.255` | **受限广播** | 本网络广播（路由器不转发） |
| `127.x.x.x` | **回环地址** | 本机协议栈内部测试（`127.0.0.1`） |

### 私有地址（RFC 1918）

公网上不可路由，仅供内网使用：

| 范围 | CIDR | 可用 IP 数 |
|------|------|-----------|
| `10.0.0.0 ~ 10.255.255.255` | `10.0.0.0/8` | ~1677 万 |
| `172.16.0.0 ~ 172.31.255.255` | `172.16.0.0/12` | ~104 万 |
| `192.168.0.0 ~ 192.168.255.255` | `192.168.0.0/16` | ~6.5 万 |

### 分类编址的致命缺陷

根本问题是**粒度断裂**——三个类的规模之间存在巨大的不连续性：

```
A 类  ████████████████████████████████████████████   1677 万 主机/网
                                                     巨大浪费
      ┊
      ┊  规模鸿沟：需要 5000 台主机的组织
      ┊  → A 类太浪费，C 类装不下 → 只能抢 B 类
      ┊
B 类  ████████████████████                            6.5 万 主机/网
                                                     仅 1.6 万个 → 迅速耗尽
      ┊
      ┊  另一鸿沟：需要 1000 台主机的组织
      ┊  → B 类浪费，C 类不够 → 继续抢 B 类
      ┊
C 类  ██                                                 254 主机/网
                                                     209 万个 → 不够用
```

- 现实需求是**连续的梯度分布**，而非三个离散点
- 一个需要 5000 台主机的组织 → A 类太浪费，C 类装不下，**只能抢 B 类**
- B 类仅 1.6 万个 → **迅速耗尽** → 地址危机

这正是促使子网划分和 CIDR 出现的直接原因——下一节会看到它们如何解决这个问题。

### 快速自测

1. `130.10.5.8` 属于哪类地址？网络号多少位？
2. 为什么 A 类网络数不是 128 个而是 126 个？
3. C 类地址 `200.1.1.0` 的广播地址是什么？

<details>
<summary>答案</summary>

1. **B 类**（首字节 130 在 128~191 之间），14 位网络号。
2. 因为 `0.0.0.0/8` 保留和 `127.0.0.0/8` 回环占用了 2 个网络号。
3. `200.1.1.255`——C 类网络号 24 位，主机号 8 位全 1。
</details>

## 二、划分子网的 IPv4 地址

### 核心思路

向主机号**借位**，将两级变为三级：**网络号 + 子网号 + 主机号**。

```
分类编址:   ┌────网络号────┐┌──────主机号──────┐
子网划分:   ┌────网络号────┐┌─子网号─┐┌─主机号──┐
                            ↑
                    从主机号中借出几位
```

**为什么划分子网？**
1. 缓解地址紧张——一个大网分几个小子网用
2. 便于管理——不同部门/楼层划到不同子网，隔离广播域
3. 提高安全——子网之间经路由器隔离

### 子网掩码

32 位，网络号 + 子网号对应位全 **1**，主机号对应位全 **0**。与 IP 地址做**逻辑与（AND）**即可提取网络地址。

```
IP 地址:   192.168.1.10    11000000 10101000 00000001 00001010
子网掩码:  255.255.255.0   11111111 11111111 11111111 00000000
          ─────────────────────────────────── AND
网络地址:  192.168.1.0     11000000 10101000 00000001 00000000
```

> 子网掩码中 **1 的个数**就是网络前缀长度。`255.255.255.0` = `/24`。

### 子网划分实例

**需求**：将 `192.168.1.0/24` 划分为 4 个子网。

从主机号（8 位）中借 2 位做子网号（$2^2 = 4$ 个子网），每子网剩 6 位主机号（$2^6 - 2 = 62$ 台主机/子网）：

| 子网号 | 子网地址 | 可用地址范围 | 广播地址 |
|--------|---------|-------------|---------|
| 00 | `192.168.1.0/26` | `192.168.1.1 ~ .62` | `192.168.1.63` |
| 01 | `192.168.1.64/26` | `192.168.1.65 ~ .126` | `192.168.1.127` |
| 10 | `192.168.1.128/26` | `192.168.1.129 ~ .190` | `192.168.1.191` |
| 11 | `192.168.1.192/26` | `192.168.1.193 ~ .254` | `192.168.1.255` |

> 每子网减 2（网络地址 + 广播地址）。4 × 62 = 248 台，比原 C 类的 254 少 6 台——子网划分自身消耗了地址。

## 三、无分类编址 CIDR

**CIDR（Classless Inter-Domain Routing）**彻底抛弃 ABC 分类，使用**网络前缀** + 斜线记法。

### 斜线记法

```
192.168.1.0/24   ← 前 24 位是网络前缀

地址块 = 2^(32-24) = 256 个地址
  最小地址: 192.168.1.0   (主机号全 0)
  最大地址: 192.168.1.255 (主机号全 1)
  可用地址: 192.168.1.1 ~ 192.168.1.254 (254 个)
```

### 路由聚合（超网）

CIDR 最大的贡献：把多个连续网络前缀**聚合**为一个更短的前缀——一条路由替代多条，路由表大幅缩减。

```
聚合前（8 条路由）:
  192.168.0.0/24 → eth0     192.168.4.0/24 → eth0
  192.168.1.0/24 → eth0     192.168.5.0/24 → eth0
  192.168.2.0/24 → eth0     192.168.6.0/24 → eth0
  192.168.3.0/24 → eth0     192.168.7.0/24 → eth0

聚合后（1 条路由）:
  192.168.0.0/21 → eth0     ← 前 21 位相同！
```

```
192.168.0.0 = 11000000 10101000 00000 000 00000000
192.168.1.0 = 11000000 10101000 00000 001 00000000
192.168.2.0 = 11000000 10101000 00000 010 00000000
    ⋮
192.168.7.0 = 11000000 10101000 00000 111 00000000
             └────────── 21 位相同 ──────────┘
```

### 最长前缀匹配

当多条路由都匹配目的地址时，选择**前缀最长（最具体）**的那条：

```
路由表:
  192.168.0.0/16  → 接口 A  (笼统："去北京")
  192.168.1.0/24  → 接口 B  (具体："去北京朝阳区建国路")

目的地址 192.168.1.10:
  ✓ 匹配 /16  
  ✓ 匹配 /24  → 选 /24！更具体 → 从接口 B 转发
```

## 四、地址规划：FLSM vs VLSM

### 定长子网掩码（FLSM）

所有子网使用**相同的子网掩码**。简单但浪费——不管子网实际需要多少台主机都分一样大。

### 变长子网掩码（VLSM）

不同子网使用**不同长度的子网掩码**，按需分配：

```
需求: 子网A 60台, 子网B 10台, 子网C 5台
可用: 192.168.1.0/24

VLSM 规划 (从大到小):
  子网A: 192.168.1.0/26   (62 台可用)  ← 60+2, 刚好 /26
  子网B: 192.168.1.64/28  (14 台可用)  ← 10+2, /28 足够
  子网C: 192.168.1.80/29  (6 台可用)   ← 5+2, /29 足够
  剩余:  192.168.1.88/29  ~ 192.168.1.248/29  未分配
```

### 规划步骤

1. 需求排序：从主机数最多的子网开始
2. 确定掩码：$2^k - 2 \ge$ 所需主机数，前缀 = $32 - k$
3. 顺序分配：地址块不重叠
4. 记录剩余：为未来扩展留空间
