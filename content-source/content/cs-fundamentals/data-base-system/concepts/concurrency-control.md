# 并发控制

## 1. 活锁与死锁

|     | 活锁            | 死锁                    |
| --- | ------------- | --------------------- |
| 现象  | 事务一直等待，但有机会执行 | 事务互相等待，永远无法执行         |
| 解决  | 先来先服务         | 预防（一次封锁法、顺序封锁法）或检测+回滚 |
- 活锁产生的原因:当一系列封锁不能按照其先后顺序执行时,就可能导致一些事务无限期等待某个封锁,从而导致活锁。
- 避免活锁的简单方法是采用先来先服务的策略。当多个事务请求封锁同一数据对象时,封锁子系统按请求封锁的先后次序对事务排队,数据对象上的锁一旦释放就批准申请队列中第一个事务获得锁。
## 2. 封锁

### X 锁（写锁 / 排他锁）

某事务对数据对象上 X 锁后：
- 可读取和修改该数据对象
- 其他事务**无法**对该数据对象加任何锁

操作：`Xlock()` / `Unlock()`

### S 锁（读锁 / 共享锁）

某事务对数据对象上 S 锁后：
- 可读取但**不可修改**该数据对象
- 其他事务可以加 S 锁，但**不能加 X 锁**

操作：`Slock()` / `Unlock()`

### 锁相容矩阵

|  | S | X | — |
|--|---|---|---|
| **S** | ✅ | ❌ | ✅ |
| **X** | ❌ | ❌ | ✅ |
| **—** | ✅ | ✅ | ✅ |

## 3. 封锁协议

### 一级封锁协议

- 写前加写锁，事务结束后释放写锁
- 可防止：**丢失修改**

### 二级封锁协议

- 写前加写锁，读前加读锁，读完后释放读锁，事务结束释放写锁
- 可防止：丢失修改 + **读脏数据**

### 三级封锁协议

- 写前加写锁，读前加读锁，**事务结束**释放各锁
- 可防止：丢失修改 + 读脏数据 + **不可重复读**

> 如果所有事务都遵循三级封锁协议，那么这些事务无论怎样交叉并行，都是可串行化调度。

| 协议 | 写锁释放 | 读锁释放 | 防止丢失修改 | 防止读脏数据 | 防止不可重复读 |
|------|---------|---------|:---:|:---:|:---:|
| 一级 | 事务结束 | — | ✅ | ❌ | ❌ |
| 二级 | 事务结束 | 读完即放 | ✅ | ✅ | ❌ |
| 三级 | 事务结束 | 事务结束 | ✅ | ✅ | ✅ |

### 两段锁协议（2PL）

- 事务在对任何数据进行读写前都需要获得对该数据的封锁
- 事务在释放**任何一个**封锁后，不可再获得其他任何封锁

> **事务遵循两段锁协议是可串行化的充分条件**（不是必要条件）
> 遵循两段锁协议仍可能发生死锁
